# UF2-загрузчик для K1986BE92FI (Milandr, Cortex-M3)

Перетащи `firmware.uf2` на USB-диск `K1986VE92FI` — прошивка записана. Построен на
SPL/CMSIS из DFU-проекта (включены в `platform/`) (USB-стек SPL, Flash через `EEPROM_*`), логика
FAT/UF2/SCSI написана заново и отделена от железа.

USB-идентификатор загрузчика: `VID:PID = 1209:be92` — та же отладочная пара,
что используется в DFU-версии загрузчика.

> **Статус проверки.** Сборка ARM и хост-тесты проверяются локально и в GitHub Actions.
> Работа загрузчика на кристалле ещё требует аппаратной проверки.

## Раскладка Flash (128 КБ)

| Адрес | Размер | Назначение |
|---|---|---|
| `0x08000000` | 8 КБ | код загрузчика (линкер выдаст ошибку при переполнении) |
| `0x08002000` | 4 КБ  | страница состояния: маркер валидности + CRC32 приложения |
| `0x08003000` | 116 КБ | приложение |

**Важно:** приложения для прежнего адреса `0x08004000` необходимо пересобрать и сформировать UF2 заново.

Info-банк (заводские данные) загрузчик не трогает ни при каких условиях.

## Сборка

```
make
make test          # хост-тесты (нужны gcc и python3)
```
Первый раз прошить `build/k1986ve92fi_uf2_bootloader.bin` по SWD в `0x08000000`
(как в вашем `build_and_flash.sh`). Проверяйте размер кода: линкер ограничивает его 8 КБ.

## Приложение

* линковать на `0x08003000`, `FLASH LENGTH = 116K`; `_estack = ORIGIN(RAM)+LENGTH(RAM)-16`
  (последние 16 байт ОЗУ — под запрос входа в загрузчик);
* `SystemInit()` из SPL сам выставляет `VTOR = &__Vectors` — отдельно трогать не нужно;
* `arm-none-eabi-objcopy -O binary app.elf app.bin && python3 tools/bin2uf2.py app.bin -o app.uf2`
  (подойдёт и `uf2conv.py -f 0xE47E1D64 -b 0x08003000`);
* из приложения войти в загрузчик: `#include "boot_request.h"` → `bl_request_uf2_and_reset();`

## Когда загрузчик остаётся в режиме UF2

кнопка PB6 при старте (активный низкий, настраивается в `main.c`) · запрос из приложения ·
приложение отсутствует / не прошло проверку. Светодиод PB7: медленно мигает — ожидание,
быстро — идёт запись, горит — готово (через 500 мс после последней записи устройство само
перезагружается).

## Что защищает от «кирпича»

* адрес/размер каждого UF2-блока проверяются **до** любых действий; запись возможна только
  в `0x08003000…0x0801FFFF`; блоки вне диапазона отвергаются, Flash не меняется;
* при начале записи маркер сбрасывается — оборванное обновление не загрузится, даже если
  таблица векторов уже записана; новый маркер (с CRC32) пишется только после приёма *всех*
  блоков и успешной проверки;
* страница стирается один раз за сессию при первом обращении; повторные блоки (ОС любит
  перезаписывать) сверяются с Flash; каждое программирование проверяется чтением назад;
* код стирания/записи — в ОЗУ, на время операции прерывания запрещены; сами операции идут
  из главного цикла, а не из прерывания USB;
* образы, залитые по SWD (маркер стёрт), загружаются по проверке векторов — удобно при отладке.

## Ограничения 

* Family ID `0xE47E1D64` — отладочный, USB-идентификатор загрузчика `1209:be92`
  совпадает с DFU-версией;
* серийного номера USB нет (в предоставленном SPL нет UID кристалла);
* двойного нажатия Reset нет (вход — кнопка/запрос приложения);
* максимум 2048 блоков в файле; payload 4…476 байт, кратно 4; один LUN, только Full-Speed;
* нужен кварц 8 МГц на HSE (как в DFU-проекте); без него USB не стартует (приложение
  запускается, если оно валидно, иначе мигание светодиода).

## Первый запуск — что проверить

1. `size`/`--print-memory-usage`: код влез в 8 КБ;
2. диск монтируется в Windows/macOS/Linux; `INFO_UF2.TXT` читается;
3. копирование образа: светодиод, автоперезагрузка, приложение стартует;
4. копирование заведомо битого UF2 (адрес `0x08000000`) отвергается, загрузчик цел;
5. выдернуть USB посреди копирования → после включения остаёмся в загрузчике;
6. сборка с `-Os -flto` и без `-flto`.
