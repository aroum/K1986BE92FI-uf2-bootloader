# UF2-загрузчик для K1986BE92FI (Milandr, Cortex-M3)

Перетащи `firmware.uf2` на USB-диск `K1986VE92FI` — прошивка записана. Построен на
SPL/CMSIS из DFU-проекта (включены в `platform/`) (USB-стек SPL, Flash через `EEPROM_*`), логика
FAT/UF2/SCSI написана заново и отделена от железа.

Также доступна DFU-версия загрузчика: [K1986BE92FI-dfu-bootloader](https://github.com/aroum/K1986BE92FI-dfu-bootloader).

USB-идентификатор загрузчика: `VID:PID = 1209:be92` — та же отладочная пара,
что используется в DFU-версии загрузчика.

> **Статус проверки.** Работа загрузчика полностью проверена на реальном «железе» микроконтроллера (K1986BE92FI / MDR32F9Q2I).
> Виртуальный накопитель монтируется как USB Mass Storage, файл `CURRENT.UF2` читается, прошивка приложений через drag-and-drop работает корректно.

## Раскладка Flash (128 КБ)

| Адрес | Размер | Назначение |
|---|---|---|
| `0x08000000` | 12 КБ | код загрузчика (линкер выдаст ошибку при переполнении) |
| `0x08003000` | 4 КБ  | страница состояния: маркер валидности + CRC32 приложения |
| `0x08004000` | 112 КБ | приложение |

Info-банк (заводские данные) загрузчик не трогает ни при каких условиях.

## Сборка

```
make
make test          # хост-тесты (нужны gcc и python3)
```
Первый раз прошить `build/k1986ve92fi_uf2_bootloader.bin` по SWD в `0x08000000`
(как в вашем `build_and_flash.sh`). Проверяйте размер кода: линкер ограничивает его 12 КБ.

## Приложение

* линковать на `0x08004000`, `FLASH LENGTH = 112K`; `_estack = ORIGIN(RAM)+LENGTH(RAM)-16`
  (последние 16 байт ОЗУ — под запрос входа в загрузчик);
* `SystemInit()` из SPL сам выставляет `VTOR = &__Vectors` — отдельно трогать не нужно;
* `arm-none-eabi-objcopy -O binary app.elf app.bin && python3 tools/bin2uf2.py app.bin -o app.uf2`
  (подойдёт и `uf2conv.py -f 0xE47E1D64 -b 0x08004000`);
* из приложения войти в загрузчик: `#include "boot_request.h"` → `bl_request_uf2_and_reset();`

## Способы входа в загрузчик

Загрузчик остаётся в режиме UF2 накопителя в следующих случаях:
* **Двойной Reset** с интервалом до 500 мс;
* **Кнопка PB6** зажата при старте (активный низкий уровень, настраивается в `main.c`);
* **Программный запрос** из приложения через вызов `bl_request_uf2_and_reset()`;
* **Приложение отсутствует или повреждено** (не прошла валидация таблицы векторов или CRC32).

Индикация светодиодом (PB7):
* **Медленное мигание** — ожидание подключения / прошивки;
* **Быстрое мигание** — идёт процесс записи во Flash;
* **Непрерывно горит** — запись успешно завершена (через 500 мс после приёма последнего блока устройство автоматически перезагружается в приложение).

## Защита от сбоев и повреждения прошивки

* **Валидация адресов:** адрес и размер каждого UF2-блока проверяются строго до записи; запись разрешена только в область приложения `0x08004000…0x0801FFFF`. Любые блоки вне этого диапазона отклоняются, память загрузчика (`0x08000000…0x08002FFF`) надёжно защищена;
* **Атомарность обновления:** при начале записи маркер валидности сбрасывается. Оборванная запись не приведёт к попытке запуска неполной прошивки, даже если векторная таблица уже успела записаться. Новый маркер валидности с CRC32 записывается только после получения всех блоков и успешной верификации;
* **Кэширование и проверка:** страница стирается один раз за сессию при первом обращении; повторные блоки (характерно для операций записи в некоторых ОС) предварительно сверяются с Flash; каждая операция записи верифицируется чтением;
* **Безопасное исполнение из ОЗУ:** код стирания и записи Flash выполняется из RAM с отключенными прерываниями, исключая сбои при работе с Flash-памятью микроконтроллера;
* **Совместимость с отладкой по SWD:** если приложение прошито напрямую через J-Link/SWD (маркер CRC32 не сформирован), бутлоадер проверяет корректность указателя стека и Reset Handler и запускает приложение без лишних препятствий.

## Ограничения 

* Family ID `0xE47E1D64` — отладочный, USB-идентификатор загрузчика `1209:be92`
  совпадает с DFU-версией;
* серийного номера USB нет (в предоставленном SPL нет UID кристалла);
* двойной Reset использует зарезервированное слово ОЗУ `0x20007FF0`; при обычном запуске исправного приложения добавляется ожидание 500 мс. Сохранение ОЗУ при аппаратном сбросе требуется проверить на плате;
* максимум 2048 блоков в файле; payload 4…476 байт, кратно 4; один LUN, только Full-Speed;
* нужен кварц 8 МГц на HSE (как в DFU-проекте); без него USB не стартует (приложение
  запускается, если оно валидно, иначе мигание светодиода).

## Проверка и тестирование

Работоспособность загрузчика верифицирована на отладочной плате с К1986ВЕ92FI (MDR32F9Q2I):
* Код бутлоадера занимает ~7.5 КБ и укладывается в отведенные 12 КБ (контролируется линкером и CI);
* Диск монтируется в ОС как USB Mass Storage, файл `INFO_UF2.TXT` содержит параметры бутлоадера, а `CURRENT.UF2` позволяет вычитывать текущую прошивку;
* Drag-and-drop прошивка `.uf2` образов выполняет запись страниц Flash, валидацию CRC32, автоперезагрузку и корректный старт приложения;
* Все стресс-сценарии (частичная запись, блоки с адресами вне диапазона приложения, поврежденные блоки) валидируются автоматическими тестами `make test` с AddressSanitizer и UBSan.
